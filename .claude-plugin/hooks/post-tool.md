# Post Tool Use Hook: Auto-Capture & Auto-Sync

This hook fires after tool uses to automatically capture activities and sync memories to CLAUDE.md.

## Trigger
- Event: `PostToolUse`
- Filter: Only for `Edit`, `Write`, `Bash` tools
- Timing: Immediately after tool execution completes

## Instructions

When this hook fires after a tool use, follow these steps:

---

## Part A: Auto-Capture (Activity Logging)

### 1. Check Auto-Capture Status

First, check if auto-capture is enabled by reading `memory/pro/config.json`.

**If the file doesn't exist or `autoCapture.enabled` is `false`, skip to Part B.**

### 2. Analyze Tool Action (if enabled)

Capture metadata about what happened based on the tool:

**For Edit:**
```json
{
  "tool": "Edit",
  "file": "<file-path-that-was-edited>",
  "action": "modified",
  "timestamp": "<ISO-8601-timestamp>"
}
```

**For Write:**
```json
{
  "tool": "Write",
  "file": "<file-path-that-was-created>",
  "action": "created",
  "timestamp": "<ISO-8601-timestamp>"
}
```

**For Bash:**
Only capture significant commands (git, npm, bun, build, test, deploy):
```json
{
  "tool": "Bash",
  "command": "<command-category>",
  "details": "<brief-description>",
  "timestamp": "<ISO-8601-timestamp>"
}
```

Skip capturing for:
- `ls`, `cat`, `pwd`, `cd` (navigation)
- `echo`, `mkdir` in `memory/pro/` or `memory/` (internal operations)
- Any command that reads `memory/pro/` or `memory/` files

### 3. Append to Activity Log

Read existing activity log from `memory/pro/activity.log`, parse as JSON array.
If file doesn't exist, start with empty array `[]`.

Append the new entry to the array and write back to `memory/pro/activity.log`.

**Activity Log Format:**
```json
[
  {
    "timestamp": "2026-01-30T15:30:00Z",
    "tool": "Edit",
    "file": "src/auth/login.ts",
    "action": "modified"
  },
  {
    "timestamp": "2026-01-30T15:32:00Z",
    "tool": "Bash",
    "command": "git",
    "details": "committed changes"
  }
]
```

### 4. Exclusion Rules for Auto-Capture

Do NOT capture activities for:
- Files in `node_modules/**`
- Files in `.git/**`
- Files in `memory/pro/**` (to avoid infinite loops)
- Files in `memory/**` (to avoid infinite loops)
- Log files (`*.log`)
- Lock files (`package-lock.json`, `bun.lockb`, etc.)

---

## Part B: Auto-Sync (CLAUDE.md Updates)

### 1. Check Auto-Sync Status

Read `memory/config.json` and check if `autoSync === true`.

```bash
[ -f "memory/config.json" ] && cat memory/config.json
```

**If the file doesn't exist or `autoSync` is `false` or not set, STOP HERE.**

### 2. Check If Sync Should Trigger

Auto-sync should ONLY trigger after these AF Memory commands complete:
- `/afmem:save` - after saving a memory
- `/afmem:init` - after initializing project
- `/afmem:forget` - after deleting a memory

**How to detect:** Check if the recent tool actions were writing to `memory/memories.json`.

If the `Write` tool was used on `memory/memories.json`, trigger auto-sync.

### 3. Perform Silent Sync to CLAUDE.md

When auto-sync triggers:

**Step 3a: Read all memories**
```bash
[ -f "memory/memories.json" ] && cat memory/memories.json
```

**Step 3b: Generate the AF Memory section**

Format memories as markdown (same format as `/afmem:export`):

```markdown
## Project Context (via AF Memory)

> Auto-generated by AF Memory. Last updated: [YYYY-MM-DD HH:MM]

### [Category Name]

| Key | Value |
|-----|-------|
| **key-name** | value here |

---
```

For organizing memories, use these categories based on key names:
- **Workspace Info**: keys containing `project-name`, `workspace`, `subprojects`
- **Tech Stack**: keys containing `stack`, `framework`, `database`, `auth`, `styling`, `testing`
- **Global Preferences**: other preference-like keys
- Uncategorized keys go in a general table

**Step 3c: Check CLAUDE.md**
```bash
[ -f "CLAUDE.md" ] && cat CLAUDE.md
```

**Step 3d: Update CLAUDE.md**

- **If CLAUDE.md does NOT exist:** Create it with just the AF Memory section
- **If CLAUDE.md exists with AF Memory section:** Replace the section between `## Project Context (via AF Memory)` and the next `---` or `## ` heading
- **If CLAUDE.md exists without AF Memory section:** Append the AF Memory section at the end

### 4. Silent Operation with Minimal Output

**IMPORTANT:** This hook should operate mostly silently.

- Do NOT output verbose messages
- After sync completes, output ONLY: `Synced`
- If there's an error, report it briefly

### 5. Exclusion Rules for Auto-Sync

Do NOT trigger auto-sync for:
- Writing to any file other than `memory/memories.json`
- Reading operations
- Navigation commands

---

## Part C: Auto-Export (Cross-Provider Export)

### 1. Check Auto-Export Status

Read `memory/pro/config.json` and check if `autoExport.enabled === true`.

**If the file doesn't exist or `autoExport.enabled` is `false`, STOP (skip Part C).**

### 2. Check If Export Should Trigger

Auto-export should ONLY trigger when `memory/memories.json` was written:
- `/afmem:save` — after saving a memory
- `/afmem:init` — after initializing project
- `/afmem:forget` — after deleting a memory

**How to detect:** Same as Part B — check if the Write tool was used on `memory/memories.json`.

**If `memory/memories.json` was NOT the file written, STOP.**

### 3. Perform Silent Export to Configured Targets

Read `autoExport.targets` from `memory/pro/config.json`.

For each target, perform the export (same logic as `/afmem-pro:export --<target>`):

**For "codex":** Generate `AGENTS.md` in project root from memories
**For "cursor":** Generate `.cursor/rules/afmem-memory.mdc` from memories
**For "windsurf":** Generate `.windsurfrules` from memories

**Memory reading logic:**
1. Read `memory/memories.json`
2. Parse `memories` array
3. Skip memories where `vitality.state === "extinct"` (if field exists)
4. Group by `type` field; typeless → "Other"
5. Sort alphabetically by key within groups

**AGENTS.md format:**
```
# Project Memory (powered by AF Memory)
> Auto-generated. Do not edit manually. Source: memory/memories.json
> Last exported: <timestamp> | Memories: <count> | AF Memory Pro

## Facts
- <key>: <value>
[... grouped sections ...]

---
To update: save memories with /afmem:save in Claude Code, then /afmem-pro:export --codex
```

**Cursor MDC format:**
```
---
description: Project memory and coding context managed by AF Memory
globs: ["**/*"]
alwaysApply: true
---

# Project Memory (powered by AF Memory)
[... same grouped content ...]

<!-- Generated by AF Memory Pro. Source: memory/memories.json -->
```

**Windsurf format:** Same content as Cursor but plain markdown (no MDC frontmatter).

### 4. Update lastExport Timestamp

After export completes, update `autoExport.lastExport` in `memory/pro/config.json` to current ISO timestamp.

### 5. Silent Operation

**IMPORTANT:** This hook operates silently.
- Do NOT output verbose messages
- After export completes, output ONLY: `Exported` (or `Synced | Exported` if both Part B and C ran)
- If there's an error reading memories, report it briefly and continue

## Configuration

### Auto-Capture Config (`memory/pro/config.json`)

```json
{
  "version": "1.0",
  "autoCapture": {
    "enabled": true,
    "tools": ["Edit", "Write", "Bash"],
    "excludePaths": [
      "node_modules/**",
      ".git/**",
      "*.log",
      "memory/pro/**",
      "memory/**"
    ]
  }
}
```

### Auto-Sync Config (`memory/config.json`)

```json
{
  "autoSync": true
}
```

## Toggle Commands

**Auto-Capture:**
- `/afmem:auto-capture on` - Enable activity capture
- `/afmem:auto-capture off` - Disable activity capture
- `/afmem:auto-capture status` - Check status

**Auto-Sync:**
- `/afmem:auto-sync on` - Enable CLAUDE.md sync
- `/afmem:auto-sync off` - Disable CLAUDE.md sync
- `/afmem:auto-sync status` - Check status

**Auto-Export:**
- `/afmem-pro:auto-export on` - Enable cross-provider export
- `/afmem-pro:auto-export off` - Disable auto-export
- `/afmem-pro:auto-export targets codex,cursor` - Set targets

---

## Example Flow

1. User runs `/afmem:auto-sync on` -> `autoSync: true` saved to `memory/config.json`
2. User runs `/afmem:save api-key Use env var API_KEY`
3. Save command writes to `memory/memories.json`
4. Post-tool hook detects write to `memory/memories.json`
5. Hook checks `memory/config.json` -> `autoSync: true`
6. Hook reads `memory/memories.json`, generates markdown
7. Hook updates CLAUDE.md with new AF Memory section
8. Output: `Synced`

## Auto-Export Example Flow

1. User runs `/afmem-pro:auto-export on` -> `autoExport.enabled: true`
2. User runs `/afmem:save pkg-manager "Always use pnpm"`
3. Save writes to `memory/memories.json`
4. Part B: Auto-sync updates CLAUDE.md -> outputs `Synced`
5. Part C: Auto-export detects write to memories.json
6. Part C: Checks targets -> ["codex"]
7. Part C: Regenerates AGENTS.md from all memories
8. Output: `Exported`

---

## Pattern Analysis (Future Enhancement)

At session end, the activity log can be analyzed for patterns:
- Files edited 3+ times -> important files
- Repeated commands -> workflow patterns
- Consistent choices -> preferences

These insights can be promoted to permanent memories with user confirmation.
